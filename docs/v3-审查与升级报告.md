## 一、审查发现（按影响分级）

### A. 会让流程跑错或跑不通的问题（阻断级）

| 问题 | 证据 | 影响 |
|---|---|---|
| 历史实录检索不可执行 | §3B.0 要求「用 fetch_page 打开 debatetimer.cn/record 在搜索框检索」；实测搜索框是前端交互，`?search=` 参数无效，只能看到首页最近十余场 | 每场赛前必做的 §3B.0 实际只能「凭空整理」，与「不准编造」矛盾 |
| 自由辩规格自相矛盾 | 「4 分钟」+「≥24 次 × ≥140 字」= ≥3360 字 ≈ 12 分钟；上限 40 / 50 两种写法 | 模型无论怎么写都违反其中一条 |
| 基线阵容违反选角规则 | 推荐表中庞颖同时是正方二辩与反方一辩 | 照表自动选角即违规 |
| 赛前一辩稿被终稿覆盖 | #3 `正方-一辩稿.md` 与 #7 `<user_side>-一辩稿.md` 在持正方时同名 | 赛前版丢失，复盘无法对比 |
| 入口文件结构损坏 | §2 代码块未闭合吞掉 §2.2；§2.1 安装说明缺失；§6 指针指向不存在的 §3.x | 编排器读入口时得到错误指引 |

### B. 跨文件数字冲突（一致性）

自证计时（单边 vs 双边）、总结陈词计时标注、打岔字数（80 vs 95）、一辩稿节数（7 vs 8）与字数（600–800 vs ≥980）、
攻防表三套表头、全场字数（声称 ≥18000，实算 34,360）、首质回合数（prompts ≥5，历史日志写 ≥4）。
**根因**：同一个数字在 6 个文件里各写一遍，没有单一出处。

### C. 能力缺口（设计级）

1. **契约不可验证**：【完成】行的字数由模型自报，而模型数不准汉字。示例会话中，我自估「一千多字」的申论，lint 实测只有 821 字。
2. **无状态、不可续跑**：full 约 3.4 万字、39 个步骤，远超单次回复与常见上下文；进度看板只存在于聊天记录里。
3. **证据无核验**：要求每个论点带 URL、覆盖率 100%，却没有任何核验机制，检索失败时容易诱发编造链接。
4. **隔离模式在互动环节失效**：质询/自证/自由辩的 prompt 让一个子代理同时写问答双方。
5. **研究档案是孤岛**：8 位辩手 48 份 research 无任何引用；其中个别档案含私生活内容，缺少使用边界。
6. **输出不可协同**：只能在对话里滚动阅读；想追问某一段，只能手动描述位置；没有 Word 导出。

## 二、六个升级点

### 升级点 1 · 单一事实来源 + 一致性修复
- 新增 `rules/presets.json`，定义 39 个步骤的时长、计时方式、字数下限、回合/段数/发言次数、套语与 URL 要求；
- 修复全部 24 项冲突与错误（清单见 `CHANGELOG.md` v3.0.0）；
- 新增三种规模预设：full 34,360 / standard 23,100 / quick 11,500 字，取代死参数 `rounds`。

### 升级点 2 · 历史实录检索改用官方 MCP（已实测）
- `search_debates` / `get_debate_summary` / `batch_get_debate_summary`，免登录，全站共享 5000 次/天，批量算 1 次；
- 已知问题已写入文档并在 CLI 中处理：返回链接主机名为 127.0.0.1 时自动改写；搜索是子串匹配（「老家」0 命中，「大城市」命中）；整场总结含语音转写误差；
- 降级链：MCP → `tools/debatetimer.py` → `site:debatetimer.cn` 搜索。

### 升级点 3 · 机器校验完成契约
- `debate_ctl.py lint` 实测：字数（统一口径）、质询完整回合与质询方字数、答方实质回答、自证段数与打岔次数/长度、
  自由辩次数与正反交替、会议四人发言、动作/表情括号、小说旁白、元说明、环境描写、占位符、URL 与证据台账、
  套语、评委是否判出胜负、自报 vs 实测；
- **反稻草人**：引号里归属对方的「原话」若在前序发言中找不到，给出警告；
- `step … --status done` 在通过校验前拒绝放行。

### 升级点 4 · 会话状态、断点续跑与互动接力
- `session.json` + `transcript/` 逐步落盘；`/debate resume` 从文件而不是从记忆恢复；
- `next` 直接给出下一步的 prompt 小节、参与辩手、下限与输出文件名；
- isolated 模式下质询/自证/自由辩**逐回合接力**（prompts §1.5）；inline 模式如实声明为软隔离。

### 升级点 5 · 证据台账与人设护栏
- `evidence.md`：✅已核验 / ⚠️待核实 / ❌已证伪；URL 只能来自本会话真实工具返回；查不到出处 → 标【待核实】、不写 URL；
- `PERSONA_PROTOCOL.md`：按环节渐进加载 research；只用公开的辩论人格，不引入私生活，不伪造真人原话，
  不复用贬损性标签；导出文件默认附 AI 模拟声明。

### 升级点 6 · 辩论协同台（脚手架）
- **展示**：按赛程导航、逐段渲染、正反方配色、校验结果与违规段落定位、1.5 秒实时同步、跟随直播、全场搜索；
- **导出**：单文档 / 整场实录 / 全部稿件 → Word（纯标准库 OOXML，宋体小四、黑体标题、楷体引用、A4、页码）/ Markdown / HTML / 打印 PDF / ZIP；
  可选清理契约行、附 AI 模拟声明、附协同问答；
- **复制位置提问**：每段的「复制位置」、划词「复制位置并提问」、跨环节引用篮、提问对象与意图；
  剪贴板内容包含 `debate://<会话>/<环节>#b<N>` 锚点与原文；Agent 端 `locate` **以原文为准**定位，
  段落编号漂移也能纠偏（测试中锚点 b9 被纠正为 b10）；待答队列配合 `/ask`；答案回写后显示在原文旁。

## 四、已知限制与后续建议

1. **未运行完整辩论**（遵照「不用运行」）。各环节 prompt 的实际产出质量仍取决于所用模型；lint 能保证「格式与数量」，不能保证「质量」。
2. debatetimer MCP 处于**公测期**，额度全站共享；整场总结有转写误差，只能作为线索。
3. lint 中的「旁白 / 环境描写 / 引用核对」是启发式规则，可能误报；因此设为「警告」，不阻断流程。
4. 部分研究档案含私生活内容。v3 用护栏禁止使用，**未删除原作内容**；如需彻底清理，建议原作者删改这些小节。
5. 浏览器在非 HTTPS 的局域网地址下可能禁用剪贴板 API；协同台会自动降级为手动复制。
6. 可继续做：评委打分表（按维度量化）、用户本人作为某一辩位**真人上场**的模式、协同台中直接编辑并回写段落。

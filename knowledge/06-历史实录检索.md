# 历史实录检索（debatetimer.cn）

> **核心理念**：「读过百场辩论实录，下笔如有神」。
> 在自己埋头立论之前，先看看**别人在这道题（或近似题）上是怎么打的、怎么输的、怎么赢的**。

---

## 一、为什么必须先检索

辩论圈有句话：「**任何一道辩题，世界上一定有人比你想得更深。**」

赛前不检索的辩手会陷入三个陷阱：

1. **重复发明轮子**：自己想破头的论点，前人 5 年前就打过；
2. **重复踩同样的坑**：前人因为某个论点输得很惨，你不查就还会再输一次；
3. **不知道对方会打什么**：经典辩题往往有"必打 5 招"，你不知道就只能临场被动。

→ **检索 = 用别人 100 场比赛的经验武装自己。**

---

## 二、检索源：debatetimer.cn

> 「辩之竹辩论计时器」官网，自 2019 年起服务全国数十万场辩论赛，
> 公开实录库是华语辩论圈最大的真实辩论文本库。

### 2.1 URL 模式

| 用途 | URL |
|---|---|
| 录音库主页（按时间倒序）| `https://debatetimer.cn/record` |
| 单场实录页 | `https://debatetimer.cn/record/{uuid}` |
| 比赛大厅页 | `https://debatetimer.cn/lobby/{uuid}` |
| 备赛助手（需登录）| `https://debatetimer.cn/workbench` |

### 2.2 主页可看到的元数据

主页列出每场比赛：
- 比赛名（如「武汉大学金秋辩论赛」）
- 日期
- 正方辩题 + 反方辩题
- 跳转链接

### 2.3 单场实录页能拿到什么

| 数据 | 价值 |
|---|---|
| **完整 14 环节文字稿** | 正一申论、反四质询、反一申论、…… 全场逐字录（网页端，需人工浏览） |
| **AI 整理的论述流程**（豆包整理）| 每位辩手的论点 6-8 步浓缩成清单 |
| **质询攻防的真实对话** | 知道高水平质询长什么样 |
| **结辩稿原文** | 直接学习金句、价值升华怎么写 |

### 2.4 ★v3 官方 MCP（Agent 首选的检索通道）

> 网页的搜索框是前端交互：fetch 类工具抓 `https://debatetimer.cn/record` 只能拿到首页最近十余场，
> `?search=` 参数无效（2026-10 实测）。因此 Agent 必须使用官方 MCP。

| 项目 | 内容 |
|---|---|
| 端点 | `https://debatetimer.cn/api/mcp`（Streamable HTTP；普通 JSON-RPC POST 即可） |
| 安装 | `npx add-mcp https://debatetimer.cn/api/mcp` |
| 额度 | 公测期免登录，**全站共享 5000 次/天**；批量接口一次只算 1 次 |
| `search_debates` | `{query (1–100 字), searchType: topic \| team \| tournament, page, pageSize ≤ 30}` → 场次列表（matchId、正反辩题、队伍、赛事、日期、是否加锁） |
| `get_debate_summary` | `{matchId, passcode?}` → 整场总结（双方判断标准 / 分论点 / 事实佐证 / 双方交锋 / 结辩强化） |
| `batch_get_debate_summary` | `{requests: [{matchId, passcode?}] ≤ 20}` → 批量整场总结 |
| 限制 | 不提供音频、逐字稿和分环节总结；隐藏的比赛不可检索；加锁的比赛需要口令 |

**已知问题与对策**：

1. 返回的 `recordPageUrl` 主机名是 `127.0.0.1` → 一律改写为 `https://debatetimer.cn/record/<matchId>`；
2. 搜索是**辩题子串匹配**：「回老家 发展」「老家」可能 0 命中，而「大城市」能命中「逃离/逃回大城市」系列——要主动换近义、对偶、上位概念；
3. 整场总结来自录音转写 + AI 整理，**会有错字与缺段**（例如把「西贝预制菜」识别成「西类预制食品」），
   其中的数据只能当线索，引用前必须二次检索原始出处并登记证据台账。

命令行兜底（与 MCP 同一接口，纯标准库）：

```bash
python3 tools/debatetimer.py search "大城市" --size 20               # 关键词检索
python3 tools/debatetimer.py search "华语辩论世界杯" --type tournament
python3 tools/debatetimer.py batch <id1> <id2> <id3> --save <session>/research   # 批量取总结并存档
```

## 三、检索三步法

### Step 1 · 关键词检索（MCP `search_debates`）

**优先级**（从短到泛，因为是子串匹配）：
1. **辩题核心短语**（如「人格独立」「回老家」）
2. **辩题核心词**（如「独立」「老家」「返乡」）
3. **对偶 / 上位概念**（如「大城市」「小城市」「物质 精神」）
4. **按赛事 / 队伍检索**：`searchType=tournament`（如「新国辩」）或 `team`

每组关键词记录命中数；0 命中时立刻换词，不要原词重试。

### Step 2 · 获取整场总结（MCP `batch_get_debate_summary`）

挑 3–8 场相关场次一次批量获取，提取：

```text
- 比赛名 + 日期 + 实录链接（https://debatetimer.cn/record/<matchId>）
- 正反方辩题原文
- 双方判断标准、分论点、事实佐证
- 双方交锋：谁质疑了什么、对方怎么回应（含「未直接回应」的漏洞）
- 双方结辩的最后强化
```

需要逐字稿或金句原文时，把实录链接交给用户在网页端查看，**不要**凭总结臆造原话。

### Step 3 · 整理"敌情通报"

把所有抓取的实录信息整理成一份 `历史实录敌情通报.md`，结构如下：

```markdown
# 历史实录敌情通报｜{本场辩题}

## 检索覆盖范围
- 检索关键词：{...}
- 命中 N 场相关实录
- 时间跨度：{最早日期} 至 {最近日期}

## 同题实录（辩题完全相同或几乎相同）
### 实录 1：{比赛名}（{日期}）
- URL：{...}
- 正方主论点：1)... 2)... 3)...
- 反方主论点：1)... 2)... 3)...
- 评委判决：{正/反/未公开}
- 关键金句：{...}
- 值得学习的招式：{...}
- 值得规避的失误：{...}

### 实录 2：...

## 近题实录（同主题不同切角）
### 实录 N：...

## 综合提炼

### 1. 历史上正方惯用的 3-5 个论点
| # | 论点 | 出处 | 攻防表现 |
|---|---|---|---|

### 2. 历史上反方惯用的 3-5 个论点
| # | 论点 | 出处 | 攻防表现 |
|---|---|---|---|

### 3. 经典攻防点 ≥ 3 处
- 攻防点 A：正方常打 ___，反方常用 ___ 接住
- 攻防点 B：...

### 4. 历史上输方的典型失误
- 失误 1：{描述} → 应规避方法：{...}
- 失误 2：...

### 5. 我方可借鉴的金句 / 例子 / 数据
- {引用 + 出处}
```

## 四、检索的伦理与边界

### 4.1 ✅ 可以做的

- 学习历史辩论的**论证结构**、**攻防套路**、**经典案例**；
- 引用名家金句时**标注出处**；
- 借鉴对方可能采用的论点，提前准备反击。

### 4.2 ❌ 不能做的

- **整段照抄**历史实录的辩稿（违反学术诚信，评委一听就知道是抄的）；
- **冒充原创**金句（必须标注"借用自 {比赛名} {辩位}"）；
- **泄露**对手赛前可能不知道的资料给对手；
- **过度依赖**——历史是参考，不是答案。本场辩题可能有新的切角。

### 4.3 检索失败时的降级方案

| 情况 | 处理 |
|---|---|
| MCP 未安装 / 调用失败 | `python3 tools/debatetimer.py` → 仍失败则用搜索引擎 `site:debatetimer.cn {关键词}` |
| 额度用尽（quotaRemaining = 0） | 改用 `site:debatetimer.cn` 搜索；次日额度重置 |
| 核心短语 0 命中 | 降级到核心词 → 对偶/上位概念 → 赛事/队伍检索 |
| 仍无结果 | 切换到通用搜索引擎（Skill(multi-search-engine)）查"{辩题} 立论"或"{辩题} 一辩稿" |
| 完全无任何资料 | 跳过 §3B.0，直接进入 §3B.1 自主立论，并在敌情通报里写明"未检索到先例" |

---

## 五、检索的时间预算

| 子任务 | 预算时间 |
|---|---|
| Step 1 MCP 关键词检索（2–4 组） | 1 分钟 |
| Step 2 批量获取 3–8 场整场总结 | 3 分钟 |
| Step 3 整理敌情通报 | 4 分钟 |
| **合计** | **约 8 分钟** |

如果命中实录数特别多（> 10 场），优先抓取**最近 3 场 + 评委明确判决的 2 场**，
而不是全部抓。质量 > 数量。

---

## 六、检索后的下一步

完成敌情通报后，立刻进入 §3B.1 论点架构讨论。
讨论开场，**主持辩手**应主动引用敌情通报：

> "我们先看一下历史上这道题怎么打的。根据敌情通报，正方常用的 3 个论点是 A/B/C，
> 反方常用的 3 个论点是 X/Y/Z。其中 R{N} 那场比赛反方输在 ___，我们要避坑。
> 现在开始我们自己的架构讨论..."

→ 这样的开场会让整场赛前准备**站在巨人肩膀上**。
